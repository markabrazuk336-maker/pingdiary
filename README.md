# PingDiary

Тест скорости интернета, который ведёт дневник. Каждый замер — загрузка, отдача, пинг и джиттер — сохраняется прямо в браузере, получает метку («Wi-Fi кухня», «LTE», «кабель») и потом сравнивается с любым другим замером.

Обычные спидтесты отвечают на вопрос «сколько сейчас». PingDiary отвечает на вопрос **«стало лучше или хуже — и где»**.

🌐 **[Открыть сайт](https://markabrazuk336-maker.github.io/pingdiary/)**

---

## Что умеет

- **Замер** — загрузка, отдача, пинг и джиттер, живой график хода теста и определение провайдера, IP и ближайшей точки присутствия Cloudflare.
- **Дневник** — все замеры в таблице с поиском, сортировкой и метками. Метку можно поставить или поменять в один клик прямо в строке.
- **Сравнение** — два любых замера рядом: столбики, разница в процентах и вердикт. Плюс средние значения по меткам: сразу видно, где в квартире интернет проседает.
- **Статистика** — график динамики за 7/30 дней или всё время, среднее, медиана, лучший и худший результат, и распределение скорости по времени суток.
- **Экспорт и импорт** — JSON (с ним же можно перенести дневник на другое устройство) и CSV для Excel.
- Тёмная и светлая темы, русский и английский языки, полностью адаптивная вёрстка.
- Пробел запускает тест, если фокус не в поле ввода.

## Как это устроено

Сайт — **чистая статика**: HTML, CSS и ES-модули на JavaScript. Ни сборки, ни зависимостей, ни бэкенда — репозиторий можно просто выложить на GitHub Pages, и он заработает.

Трафик для замера идёт через публичные CORS-эндпоинты Cloudflare (`speed.cloudflare.com`) — те же, что использует их собственный спидтест:

| Что меряем | Как |
|---|---|
| Пинг | 12 запросов `/__down?bytes=0`, из RTT вычитается время обработки на сервере (`Server-Timing: cfRequestDuration`), берётся медиана |
| Джиттер | Средняя разница между соседними пингами |
| Загрузка | 4 параллельных потока `/__down`, 8 секунд, байты считаются на лету через `ReadableStream` |
| Отдача | 3 параллельных потока `POST /__up`, 6 секунд |

Две вещи, ради которых стоило писать движок самому:

1. **Разгон не считается.** Первые 1.2 секунды TCP только раскачивается — этот участок в итоговую цифру не попадает, иначе результат занижается.
2. **Отдача считается по подтверждённым кускам.** `xhr.upload.onprogress` сообщает байты, ушедшие в буфер сокета, а не принятые сервером, — на старте он завышает скорость в разы. Поэтому в итог идут только куски, которые ушли целиком, а время берётся от первой отправки до последнего подтверждения. Прогресс при этом всё равно используется — но только для «живой» стрелки.

Замеры лежат в `localStorage`, никуда не отправляются и никакой аналитики на сайте нет.

## Локальный запуск

ES-модули не грузятся с `file://` — нужен любой локальный сервер. В репозитории лежит готовый скрипт без зависимостей:

```powershell
.\dev-server.ps1
```

Откроется на `http://localhost:8080/`. Порт меняется флагом `-Port 8081`.

Если есть Node или Python под рукой, подойдёт и любой из привычных вариантов:

```bash
npx serve .
```

## Публикация

Workflow `.github/workflows/pages.yml` выкладывает корень репозитория на GitHub Pages при каждом пуше в `main`. Один раз нужно включить Pages в настройках репозитория: **Settings → Pages → Source: GitHub Actions**.

## Структура

```
index.html          разметка всех четырёх вкладок
styles.css          тема, сетка, адаптив
src/engine.js       движок замера: пинг, загрузка, отдача
src/storage.js      дневник в localStorage, экспорт JSON и CSV
src/charts.js       графики на голом SVG
src/i18n.js         RU/EN словарь
src/format.js       форматирование чисел и дат
src/main.js         интерфейс: вкладки, таблица, сравнение, статистика
dev-server.ps1      локальный статический сервер
```

## Насколько цифрам можно верить

Браузерный замер всегда немного скромнее, чем реальная пропускная способность канала: мешают сам браузер, антивирус, Wi-Fi и расстояние до точки присутствия Cloudflare. Зато замеры сравнимы **между собой** — а дневник именно для этого и нужен: сравнивать вечер с утром, кухню с комнатой, старый тариф с новым.

Один полный тест расходует примерно 100–200 МБ трафика на быстром канале — на мобильном интернете это стоит учитывать.

## English

**PingDiary** is a browser speed test that keeps a diary. Every run — download, upload, latency, jitter — is stored locally, can be tagged (`kitchen Wi-Fi`, `LTE`, `cable`) and compared against any other run: side-by-side bars, percentage deltas, averages per tag, trends over time, and distribution by hour of day.

No build step, no dependencies, no backend — plain HTML, CSS and ES modules, deployable to GitHub Pages as is. Test traffic goes through Cloudflare's public CORS endpoints; measurements never leave your browser. UI in Russian and English, dark and light themes.

Run locally with `.\dev-server.ps1` (or any static server) and open `http://localhost:8080/`.
